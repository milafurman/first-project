2. CUSTOM CSS CAN'T BE EDITED, AND THE EDITOR FAILS AT IT SILENTLY

Design studio (/admin/appearance) is chat-only. There's no Custom CSS field, no
colour inputs, no manual mode — "Sections and pages" lists only AI-built
sections. So the chat agent is the only route to Custom CSS.

It doesn't work for this, in three escalating ways.

  (a) Asked to change one value, it APPENDS a rule instead of editing the
      existing one, and drops !important. We asked it to change

          .lf-card .aspect-square{background:#EDF4FB!important}

      to #E1EAF4. After publishing, the stylesheet contained both:

          .lf-card .aspect-square{background:#EDF4FB!important}
          .lf-card .aspect-square { background: #E1EAF4; }

      Identical selectors, so !important wins and the new rule is dead. The
      publish reported success and nothing changed on the page — confirmed by
      computed style, still rgb(237,244,251).

      A publish that succeeds and has no effect is worse than an error.

  (b) Told explicitly to delete the old rule and replace it carrying
      !important, it now says it can't do it. I tried this myself, by hand, in
      Design studio — not through the API and not through an agent.

  (c) So there's currently no supported way for me to change one line of my own
      Custom CSS.

For completeness, so you don't chase the wrong thing: the same stylesheet
validates cleanly through your agent design endpoint — a dry run came back ok
with no refused rules. Your API is fine. The gap is that the admin offers no
equivalent, and the chat agent mishandles CSS.

Could you either expose a plain Custom CSS textarea in Design studio, or fix the
